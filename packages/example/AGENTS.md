This package copies e2e spec files and app content from the external `cypress-example-kitchensink` npm package into the Cypress repository, where the specs are used to scaffold new user projects and the app is published to `https://example.cypress.io`.

**Key Commands**

```bash
# Copy kitchensink specs and app into this package, then build the deployable site
yarn workspace @packages/example build

# Unit tests (vitest) for the URL rewrites in bin/convert-content.ts
yarn workspace @packages/example test

# Lint (ESLint 9 flat config, eslint.config.ts)
yarn workspace @packages/example lint

# Deploy app content to GitHub Pages (production!)
yarn workspace @packages/example deploy
```

**Architecture**

- `lib/example.ts` — The package's runtime API: `getPathToE2E()` returns the path to `cypress/e2e`, which `data-context`'s codegen templates use to scaffold example specs. `index.js` and `index.d.ts` re-export it.
- `bin/build.ts` — Copies `app/` and `cypress/` out of the installed `cypress-example-kitchensink`, then runs `bin/convert.ts`.
- `bin/convert.ts` / `bin/convert-content.ts` — Rewrite the copied HTML and specs to point at `https://example.cypress.io` instead of the kitchensink's `localhost:8080` dev server.
- `gulpfile.js` — Revisions the `app/` assets into `build/` and copies `CNAME` there; `build/` is what `deploy` publishes.
- `cypress.config.js` — Cypress config for running the example specs (`test-e2e`).

**Gotchas / Notes**

- Do not edit any files in `cypress/` or `app/` directly. All changes must be made in the upstream [`cypress-example-kitchensink`](https://github.com/cypress-io/cypress-example-kitchensink) repository and then pulled in by bumping the `devDependency` version.
- `cypress/`, `app/` and `build/` are gitignored and never committed. They are regenerated by every root `yarn build` (and by the local postinstall, which runs it), and `cypress/` ships with the package through `files`.
- To update the example content: bump `cypress-example-kitchensink` in `package.json`, run `yarn` and `yarn workspace @packages/example build` to check the result locally, then open a PR. The PR carries only the `package.json` and `yarn.lock` changes.
- Running `deploy` publishes directly to the GitHub Pages production site; verify the `./build` directory first.
- `build-prod` compiles `lib/*.ts` to `lib/*.js` in place; that output is gitignored, ignored by ESLint, and removed by `clean`.
- `lib/` is pulled into the `vue-tsc` type-check of `app`, `launchpad` and `frontend-shared` (via `data-context`'s codegen templates), which target ES modules. `export =` there fails those jobs with TS1203 even though this package's own `check-ts` passes — use `export default`, and run the root `yarn check-ts` rather than only this workspace's.
- That default export is why `index.js` unwraps `.default`. The two go together: without the unwrap, `require('@packages/example')` yields `{ default: … }` and `getPathToE2E` is undefined for any CommonJS consumer. Keeping `module.exports` the plain object is what makes the package resolve identically under `ts-node`, `tsc` output, and the esbuild snapshot bundle.

**Auto-Generated Files**

- `cypress/` and `app/` — Copied from `cypress-example-kitchensink` by the `build` script; do not edit by hand.
- `build/` — The revisioned site produced by `gulpfile.js` for `deploy`.
- `lib/*.js` — `build-prod` output.
