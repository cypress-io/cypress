This package answers one question: **was this Cypress process invoked by an AI
coding agent, and which one?** It fingerprints the environment block against a
table of marker variables and returns a fixed name from a closed set.

It is intentionally **pure, dependency-free TypeScript** — no `fs`, no `http`, no
runtime deps, and no reads of anything but the environment object it is handed.
That is what lets both the Node-side packages and the `cypress` CLI bundle it
without taking on a new runtime dependency.

**Key Commands**

```bash
# Build TypeScript to dist/
yarn workspace @packages/agent-info build

# Run tests
yarn workspace @packages/agent-info test
```

**Architecture**

- `lib/index.ts` — the whole package: the `AgentName` union, the `AGENTS`
  detection table, and the `detectAgent()` / `isAgent()` entry points.

**Adding an agent**

Three edits, all in `lib/index.ts` plus its spec:

1. Add the name to the `AgentName` union (keep it alphabetical).
2. Add a row to `AGENTS` — either bare env var names, or `envMatcher(key, regex)`
   when the variable's presence alone is not conclusive.
3. Add a row to the `detects %s` table in `lib/__spec__/index.spec.ts`.

**Gotchas / Notes**

- **Table order is significant.** IDEs are listed last so that an agent running
  inside an IDE is reported as the agent, not the IDE.
- **Only fixed names leave the machine.** `AI_AGENT` is free-form and often carries
  a version, so it is narrowed to a known name or `'other'` — never forwarded
  verbatim. Callers report this value off-machine; keep it that way.
- **Prefer a specific marker to a substring.** A regex that matches anywhere in a
  path will also match a user whose home directory happens to be named after the
  agent. Anchor on a path separator and end-of-string.
- **The TTY gate biases toward "human".** Some variables are set by both an IDE's
  integrated terminal and its CLI agent. `envMatcher(..., { noTTY: true })` skips
  those when either stdin or stdout is a terminal — both are checked because
  redirecting one leaves the other attached (`cypress run | tee log.txt`).
  Mislabelling a human as an agent is worse than missing an agent.
- This is consumed by the `cypress` CLI, so it runs on the **user's** Node — the
  `engines.node` range in [`cli/package.json`](../../cli/package.json), which is a
  lower floor than the dev or bundled Node.
- `dist/` is generated by `tsc`; do not edit by hand.
